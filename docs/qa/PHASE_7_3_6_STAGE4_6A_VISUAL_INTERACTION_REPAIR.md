## Implemented repairs

### Shared mobile overlays

- Navigation and account menus now use one coordinated state boundary.
- Opening either menu closes the other.
- Navigation is bounded to the dynamic viewport.
- Only the authorized navigation list scrolls.
- Body scrolling is locked only while the navigation drawer is open.
- Escape and close controls return focus to the opening control.
- Route and browser-history changes close active overlays.
- Permission-filtered links remain generated by the server shell.

### Worker cards

- Product images and fallbacks use a compact 96–112 pixel presentation.
- Identity, route, assignment, quantity, progress, and actions have bounded
  layout regions.
- `PROBLEM` cards no longer expose normal processing actions.
- A `PROBLEM` card explains that work is paused and exposes only Open Problem
  and Details.
- Read-only cards display the permission reason and Details.
- Pick, Mark, Assembly, and Pack retain only their existing supported actions.
- Existing server actions, route decisions, request IDs, and prerequisite
  services were not replaced.

### Universal Scanner

- Desktop controls remain a bounded 360-pixel column.
- Result cards have separate image, identity/reference, workflow, and action
  regions.
- Mobile results stack without hiding actions.
- Lookup duration now has a descriptive label.
- The same Tracking ID can legitimately return two candidates:
  Customer Order Pick and package Pack. They are preserved and clearly labelled
  because they represent different action scopes, not a duplicated resolver
  result.

### Data Management

- Quarantine, archive, restore, and permanent actions now have distinct visual
  hierarchy.
- Disabled actions show their reason without opening unusable controls.
- Expanded reauthentication controls have a visible Cancel action.
- Escape and Cancel close the expanded panel and restore focus.
- Controls remain at least 44 pixels high and mobile buttons use bounded widths.
- Existing owner authorization, password reauthentication, typed confirmation,
  one-use authorization, durable receipt, and authoritative server action are
  unchanged.
